# ระบบประเมินพนักงาน (Employee Evaluation System)

เว็บแอปประเมินผลการปฏิบัติงาน: หน้าบ้าน HTML/CSS/JavaScript, หลังบ้าน Node.js + Express, ฐานข้อมูล Oracle Database (13 ตารางตามเอกสาร + work_schedules + deadline_extensions)

## บทบาทผู้ใช้ (4 บทบาทตาม Use Case)

| บทบาท | Use Case | เมนูหลัก |
|---|---|---|
| **พนักงาน** (`employee`) | UC-01 ถึง UC-06 | รอบการประเมิน, เป้าหมายของฉัน (ส่งให้พี่เลี้ยง), ประเมินตนเอง (ส่งให้พี่เลี้ยง), ผลประเมินของฉัน (รับทราบ / ส่งข้อสงสัย) |
| **พี่เลี้ยง** (`mentor`) | UC-07 ถึง UC-11 | ตรวจสอบเป้าหมาย (อนุมัติ/ส่งกลับ), แบบประเมินตนเอง (ส่งกลับแก้ไข), ประเมินพนักงาน (ให้คะแนน + ข้อเสนอแนะ, บันทึกร่าง, ส่งผลให้ HR) — เห็นเฉพาะพนักงานที่ได้รับมอบหมาย |
| **HR** (`hr`) | UC-12 ถึง UC-16 | รอบการประเมิน (ช่วงเวลา + ขยายเวลารายบุคคล), เกณฑ์และแบบประเมิน, ติดตามสถานะ (มอบหมายพี่เลี้ยง, รายการล่าช้า), ตรวจสอบและยืนยันผล (ปรับเทียบ / ส่งกลับให้พี่เลี้ยง / ยืนยัน / เผยแพร่), รายงานสรุปผล, ประวัติการเปลี่ยนแปลง |
| **ผู้บริหาร** (`executive`) | UC-17, UC-18 | ภาพรวมสถานะและผลการประเมิน (เลือกรอบ/หน่วยงาน), รายงานสรุปผล + CSV — ดูอย่างเดียว เห็นคะแนนเฉพาะผลที่ HR ยืนยันแล้ว |

ขั้นตอนการประเมิน (evaluations.status):
`not_started` → พนักงานส่งประเมินตนเอง `pending_mentor` (พี่เลี้ยงส่งกลับ = `returned`) → พี่เลี้ยงประเมิน `draft` / ส่ง `pending_hr` (HR ส่งกลับให้พี่เลี้ยง = `draft`) → HR ปรับเทียบและยืนยัน `confirmed` → เผยแพร่ `published` → พนักงานรับทราบ `acknowledged`

พี่เลี้ยงของพนักงานแต่ละคนเก็บที่ `evaluations.mentor_id` (รายรอบ) — HR เปลี่ยนได้ที่หน้า "ติดตามสถานะ" และเมื่อเปิดรอบใหม่ ระบบคัดลอกพี่เลี้ยงจากรอบก่อนให้

## ไฟล์สำคัญ

- `index.html`, `css/`, `js/` — หน้าบ้าน (หน้าจอแยกไฟล์ใน `js/views/`)
- `server/server.js` — หลังบ้าน REST API
- `server/.env` — ค่าการเชื่อมต่อฐานข้อมูล (**ห้ามอัปขึ้น Git / ห้ามส่งให้คนอื่น**) ดูตัวอย่างที่ `server/.env.example`
- `sql/00_create_user_as_admin.sql` — สร้างบัญชีฐานข้อมูล EVAL_APP (รันด้วย SYSTEM ครั้งเดียว)
- `sql/03_document_schema.sql` — สร้าง 13 ตาราง + ตารางเสริม 2 ตาราง + ข้อมูลตั้งต้น (รันด้วย EVAL_APP, รันซ้ำได้ จะล้างข้อมูลเดิม) ช่วงเวลาของรอบตัวอย่างคำนวณจากวันที่รันไฟล์ จึงทดลองส่งเป้าหมาย/ประเมินตนเองได้ทันที
- `sql/04_hotel_departments.sql` — เปลี่ยนแผนก/ตำแหน่งเป็นแบบโรงแรมโดยไม่ล้างข้อมูล (ถ้ารัน `npm run db:reset` ไม่ต้องใช้ไฟล์นี้)
- `sql/01_schema_and_seed.sql`, `sql/02_add_features.sql` — โครงสร้างรุ่นเก่า **ไม่ต้องใช้แล้ว**

## วิธีรัน (เลือก 1 ทาง)

### ทาง A — GitHub Codespaces (ง่ายที่สุด ไม่ต้องติดตั้งอะไรเลย)
1. เปิดหน้า repo บน GitHub → ปุ่มสีเขียว **Code** → แท็บ **Codespaces** → **Create codespace on main**
2. รอ 3–5 นาที ระบบจะสร้าง Oracle + บัญชี EVAL_APP + 13 ตาราง + ไฟล์ `server/.env` + `npm install` ให้เอง
3. ใน Terminal พิมพ์
   ```bash
   cd server
   npm run db:check     # ควรขึ้น "ตารางครบ 15 ตาราง" (ถ้าขึ้นเชื่อมต่อไม่ได้ ให้รออีก 1-2 นาที)
   npm start
   ```
4. แท็บ **PORTS** → พอร์ต 3000 → กดรูปลูกโลกเพื่อเปิดเว็บ

คำสั่งที่ใช้บ่อยใน Codespace (พิมพ์ในโฟลเดอร์ `server`)

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm start` | เริ่มเว็บ (หยุดด้วย Ctrl+C) |
| `npm run db:check` | ตรวจว่าเชื่อม Oracle ได้และตารางครบ |
| `npm run db:reset` | ล้างข้อมูลทั้งหมด แล้วสร้างข้อมูลทดลองใหม่ |

> Codespace ที่สร้างไว้ก่อนเพิ่มโฟลเดอร์ `.devcontainer` ต้อง Rebuild หนึ่งครั้ง: กด `Ctrl+Shift+P` → **Codespaces: Rebuild Container**

### ทาง B — Docker บนเครื่องตัวเอง (Windows / Mac / Linux)
1. ติดตั้ง **Docker Desktop** แล้วเปิดโปรแกรมไว้
2. `git clone <ลิงก์ repo>` แล้วเข้าโฟลเดอร์โปรเจกต์
3. พิมพ์ `docker compose up` แล้วรอจนขึ้น `Evaluation app listening on http://0.0.0.0:3000` (ครั้งแรก 3–5 นาที)
4. เปิด http://localhost:3000

| คำสั่ง (ที่โฟลเดอร์โปรเจกต์) | ใช้ทำอะไร |
|---|---|
| `docker compose up -d` | เริ่มแบบทำงานเบื้องหลัง |
| `docker compose logs -f app` | ดู log ของเว็บ |
| `docker compose restart app` | รีสตาร์ตเว็บหลังแก้โค้ด |
| `docker compose down` | หยุด (ข้อมูลยังอยู่) |
| `docker compose down -v` | หยุดและลบฐานข้อมูล (เริ่มใหม่ด้วยข้อมูลทดลอง) |

ดูตารางด้วย SQL Developer: Host `localhost` · Port `1522` · Service name `FREEPDB1` · User `EVAL_APP` · Password `orcl`

### ทาง C — Oracle XE ที่ติดตั้งในเครื่อง Windows (แบบเดิม)
1. SQL Developer → connection ของ EVAL_APP → เปิด `sql/03_document_schema.sql` → กด **F5**
2. คัดลอก `server/.env.example` เป็น `server/.env` แล้วแก้ `DB_PASSWORD` และ `DB_CONNECT_STRING=localhost:1521/XEPDB1`
3. Terminal: `cd server` → `npm.cmd install` (ครั้งแรก) → `npm.cmd start` → เปิด http://localhost:3000

### ไฟล์ที่ใช้ตั้งค่าอัตโนมัติ
- `.devcontainer/` — ตั้งค่า Codespace (container `app` สำหรับเขียนโค้ด + container `oracle`)
- `docker-compose.yml` — รันทั้งระบบด้วย Docker
- `db/init/01_setup.sh` — รันครั้งแรกที่สร้างฐานข้อมูล: สร้างบัญชี EVAL_APP และรัน `sql/03_document_schema.sql`
- `server/db-tools.js` — คำสั่ง `npm run db:check` / `db:reset`
- รหัสผ่าน `orcl` และ `OracleAdmin123` ในไฟล์เหล่านี้เป็นค่าทดลองสำหรับเครื่องพัฒนาเท่านั้น

## กติกาที่ระบบบังคับ (Business Rules)

- **BR-EVAL-03 / BR-EVAL-07** พนักงานส่งเป้าหมายและแบบประเมินตนเองได้เฉพาะในช่วงเวลาของขั้นตอนนั้น พ้นกำหนดแล้วส่งไม่ได้ เว้นแต่ HR อนุมัติขยายเวลารายบุคคล
- **BR-EVAL-02** ต้องมีเป้าหมายอย่างน้อยตามจำนวนที่ HR กำหนด และทุกข้อต้องมีรายละเอียด/ตัวชี้วัด
- **BR-EVAL-06** ต้องให้คะแนนครบ 20 ข้อ และกรอกช่องที่ HR ตั้งให้บังคับ ก่อนส่ง
- **UC-08** พี่เลี้ยงประเมินได้เมื่อพนักงานส่งแบบประเมินตนเองแล้ว / **UC-10** ส่งกลับได้เฉพาะก่อนพี่เลี้ยงเริ่มประเมิน / **UC-11** ส่งแล้วแก้ไม่ได้จนกว่า HR จะส่งกลับ
- **UC-07/08/10 Exception 2** พี่เลี้ยงทำได้เฉพาะพนักงานที่ได้รับมอบหมาย
- **BR-HR-03** เปลี่ยนจำนวนระดับคะแนนไม่ได้เมื่อมีการให้คะแนนแล้ว / ข้อมูลรอบเก่าดูย้อนหลังได้ทุกหน้า
- **UC-12** ช่วงวันที่ของรอบห้ามทับกัน และชื่อรอบห้ามซ้ำ

## ความปลอดภัย

- PIN เก็บเป็นค่าแฮช SHA-256 ของ `ชื่อผู้ใช้:PIN` ไม่เก็บรหัสจริง
- Backend ตรวจสิทธิ์ทุกคำขอตามบทบาท (NFR-SEC-02): พนักงานเห็นเฉพาะของตนเองและเห็นผลเมื่อเผยแพร่แล้ว, พี่เลี้ยงเห็นเฉพาะทีมของตน, ผู้บริหารดูได้อย่างเดียวและไม่เห็นคะแนนระหว่างดำเนินการ
- ทุกการเปลี่ยนแปลงสำคัญบันทึกลง `audit_logs`
