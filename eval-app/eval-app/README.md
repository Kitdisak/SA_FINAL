# ระบบประเมินพนักงาน — Oracle Database edition

เว็บไซต์เดิมถูกปรับให้ใช้ Node.js/Express เป็น Backend และ Oracle Database เป็นฐานข้อมูลกลาง โดยหน้าเว็บเรียก `/api/...` แทน `localStorage` ผู้ใช้หลายเครื่องจึงอ่าน/บันทึกข้อมูลชุดเดียวกันได้ผ่านเครือข่าย

## โครงสร้างโฟลเดอร์

- `index.html`, `css/`, `js/` — หน้าเว็บเดิม; `js/db.js` เป็น REST adapter
- `server/server.js` — API และการเชื่อมต่อ Oracle
- `server/.env.example` — ตัวอย่างค่าการเชื่อมต่อ
- `sql/00_create_user_as_admin.sql` — สร้างผู้ใช้ฐานข้อมูล (รันด้วย SYSTEM/ผู้ดูแล)
- `sql/01_schema_and_seed.sql` — สร้างตารางและบัญชีทดลอง (รันด้วย EVAL_APP)

## A. ติดตั้ง Oracle Database และสร้างตาราง

1. ติดตั้ง/เตรียม **Oracle Database** ที่จะเปิดให้เครื่องลูกข่ายเชื่อมต่อได้ เช่น Oracle Database XE หรือฐานข้อมูลของมหาวิทยาลัย/องค์กร
2. ติดตั้ง Oracle SQL Developer เพื่อจัดการฐานข้อมูล
3. เปิด SQL Developer แล้วเชื่อมต่อบัญชีผู้ดูแล เช่น `SYSTEM` ไปยัง service name ของ Oracle ที่ติดตั้ง
4. เปิด `sql/00_create_user_as_admin.sql` แล้วรันด้วย **Run Script (F5)** เพื่อสร้างผู้ใช้ `EVAL_APP` หากผู้ใช้มีอยู่แล้ว อย่ารันซ้ำ; ให้แก้ผู้ใช้/รหัสผ่านตามนโยบายองค์กร
5. สร้าง connection ใหม่ชื่อ `EVAL_APP` โดยใช้รหัสผ่านที่ตั้งไว้ และ service name เดียวกัน
6. เปิด `sql/01_schema_and_seed.sql` ด้วย connection `EVAL_APP` แล้วกด **F5 (Run Script)** ควรเห็นตาราง `EVAL_ACCOUNTS` และ `EVAL_EVALUATIONS` ใน Tables หลัง Refresh

> ค่า service name ต่างกันตามรุ่น/การติดตั้ง Oracle ตัวอย่าง XE ที่พบบ่อยคือ `XEPDB1` แต่ให้ตรวจจากการติดตั้งจริง อย่าเดา service name

## B. ติดตั้งและตั้งค่า Backend

ต้องติดตั้ง Node.js รุ่น 18 ขึ้นไปบน **คอมพิวเตอร์ที่รันเว็บ/เซิร์ฟเวอร์**

1. เปลี่ยนชื่อ `server/.env.example` เป็น `server/.env`
2. แก้ค่า `DB_USER`, `DB_PASSWORD`, `DB_CONNECT_STRING` ให้ตรงกับ Oracle Database ตัวอย่าง `localhost:1521/XEPDB1` ใช้ได้เฉพาะเมื่อ Oracle อยู่เครื่องเดียวกันและ service คือ `XEPDB1`
3. ตั้ง `SESSION_SECRET` เป็นค่าสุ่มยาว ๆ และห้ามเผยแพร่ไฟล์ `.env`
4. เปิด Terminal ในโฟลเดอร์ `eval-app/server` แล้วรัน:

   ```bash
   npm install
   npm start
   ```

5. ถ้าเชื่อมต่อสำเร็จ Terminal จะแสดง `Evaluation app listening on http://0.0.0.0:3000`
6. ทดสอบในเครื่องเซิร์ฟเวอร์โดยเปิด `http://localhost:3000/api/health` ควรได้ `{"ok":true,"database":"Oracle"}`

## C. ให้หลายเครื่องเข้าใช้งาน

1. ให้เครื่องเซิร์ฟเวอร์และเครื่องลูกข่ายอยู่ในเครือข่ายเดียวกัน (เช่น Wi-Fi/LAN เดียวกัน)
2. หา IPv4 ของเครื่องเซิร์ฟเวอร์ด้วย `ipconfig` บน Windows เช่น `192.168.1.20`
3. อนุญาต TCP port `3000` ใน Windows Firewall สำหรับเครือข่ายส่วนตัวเท่านั้น
4. บนเครื่องอื่นเปิด `http://192.168.1.20:3000` โดยแทนที่ IP ตัวอย่างด้วย IP จริงของเซิร์ฟเวอร์
5. หากเครื่องลูกข่ายเข้าไม่ได้ ตรวจสอบว่าเซิร์ฟเวอร์ยังเปิดอยู่, IP ถูกต้อง, อยู่เครือข่ายเดียวกัน และ Firewall อนุญาตพอร์ต 3000

**ห้ามเปิดพอร์ต Oracle 1521 สู่อินเทอร์เน็ตโดยตรง** หากจะใช้งานนอกเครือข่าย ควรใช้ VPN หรือ deploy ผ่าน HTTPS/reverse proxy ที่ตั้งค่าอย่างปลอดภัย และให้ผู้ดูแลระบบจัดการ firewall

| `nida` | ผู้ถูกประเมิน | `1234` |
| `anan` | ผู้ถูกประเมิน | `1234` |

PIN นี้มีไว้ทดสอบเท่านั้น ควรเปลี่ยนก่อนใส่ข้อมูลจริง ระบบตัวอย่างนี้เก็บ SHA-256 ของ `username:PIN` และ session token ในหน่วยความจำของ Node.js; เป็นโครงงานต้นแบบ ไม่ใช่ระบบยืนยันตัวตนระดับ production ควรเปลี่ยนเป็น password hashing แบบ Argon2/bcrypt, session store ถาวร, rate limiting, HTTPS, audit log และระบบจัดการ PIN ก่อนใช้งานจริง

## การทำงานของระบบ

- รายชื่อบัญชีอ่านจาก `EVAL_ACCOUNTS`
- ผลประเมินถูกเก็บเป็น JSON ใน `EVAL_EVALUATIONS.PAYLOAD` เพื่อให้หน้าฟอร์มเดิมทำงานต่อได้
- Backend ตรวจสอบสิทธิ์: ผู้ประเมินอ่านรายการ/บันทึกผลได้; พนักงานดูและตอบรับเฉพาะผลของตนเอง
- หน้าเว็บตรวจสอบข้อมูลเป็นระยะทุก 2.5 วินาที เพื่อแสดงการเปลี่ยนแปลงจากเครื่องอื่น
- ต้องเปิดเว็บไซต์ผ่าน `http://localhost:3000` หรือ IP ของเซิร์ฟเวอร์ **อย่าเปิด `index.html` ด้วยการดับเบิลคลิก** เพราะ API ต้องทำงานผ่าน Express

## หมายเหตุ

โค้ดนี้เป็นฐานเริ่มต้นสำหรับงานโปรเจกต์ ต้องทดสอบกับ Oracle Database รุ่นและ service name ที่ติดตั้งจริงก่อนส่งมอบ ระบบไม่ได้เปลี่ยนรหัส PIN ผ่านหน้าเว็บโดยอัตโนมัติ; การเปลี่ยน PIN ต้องอัปเดตค่า `PIN_HASH` ผ่านขั้นตอนฝั่งผู้ดูแลที่ปลอดภัย
